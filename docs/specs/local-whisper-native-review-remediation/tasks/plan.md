## Execution Model

- Execute exactly one numbered packet per explicit `incremental-implementation` invocation, update `todo.md` and `handoff.md`, then stop.
- Packets 01–03 remain complete under the superseded local-only rule by explicit decision `plan.remote-completion-backfill` revision 1. Any later amendment to one of those packets must use the current remote completion gate.
- Packets 04–13 implement their cross-platform behavior and CI contracts, complete their local Linux/shared checks, then commit and push their packet candidate to the existing pull-request head. Each packet remains incomplete until the exact pushed revision passes all required Linux and Windows CI jobs and every other required native/C++ check.
- Packet 14 runs the full Linux/shared matrix, fixes all defects it exposes within the approved contract, and passes the same packet-local cross-platform remote gate.
- Packet 15 remains the final separate Windows x64 package for supported-host manual validation, manual-only remediation, final cross-platform regression, and workstream closure. Automated MSVC build/test/analysis/ASan evidence is no longer deferred to Packet 15; it must already pass after every Packet 04–14 push and is rerun here as final evidence.
- The remote completion gate is two-phase. First, leave `todo.md` unchecked, record pending remote evidence in `handoff.md`, create and push the packet candidate commit, and require its exact-SHA CI to pass. Then update `todo.md` and `handoff.md`, create and push a packet completion-record commit, and require the workflows for that final pushed SHA to pass. The final check run is authoritative external evidence and does not require a self-referential follow-up commit.
- Required exact-SHA evidence includes every launched required check and, at minimum, `Pull Request Checks` jobs **Local Whisper Native Quality (Linux)**, **Local Whisper Native Quality (Windows)**, **Quality Gates**, **Package Smoke (Fedora Linux)**, and **Package Smoke (Windows)**; **Actionlint** from `Lint GitHub Actions Workflows`; all selected `Local Whisper Fixture Packaging` jobs; and every new or split native job introduced by the packet.
- A required job that is missing, cancelled, timed out, unexpectedly skipped/neutral, or unsuccessful is missing evidence. Every required Windows job must launch, execute, and conclude `success`; a skipped Windows job is never acceptable packet evidence. A non-Windows skip is acceptable only when the checked-in workflow condition and packet contract explicitly make that job inapplicable. Linux success never substitutes for Windows success or vice versa.
- If an exact-SHA CI failure was caused by the packet and is within the approved contract, fix it, add a focused regression when applicable, create and push a follow-up packet commit, and repeat the full gate. An unrelated or out-of-scope failure is recorded as a blocker and leaves the packet unchecked; it does not authorize unrelated changes.
- Plan approval is not implementation authorization. Once a Packet 04–15 execution is separately authorized, its packet-scoped conventional commits and non-force pushes to the existing PR head are part of the authorized completion contract. Force-pushes, opening or modifying pull requests, manual workflow dispatches, packaging, qualification, publishing, and releases remain separately gated.

## Global Constraints

- Preserve public IPC, renderer/preload APIs, provider behavior, settings, history, artifact schemas, package targets, persisted data, Linux acknowledgment asymmetry, and protocol version 1.
- Keep changes modular C++20 with RAII, narrow dependency injection, deterministic cleanup, strict typed errors, shared contracts, and platform APIs behind Linux/Windows boundaries.
- Do not add dependencies, metadata-keyed digest caching, unmeasured hash-pass removal, `clang-cl`, Windows clang-tidy, unsupported Windows sanitizer claims, generated build outputs, or release/qualification actions.
- Use synthetic non-sensitive tests and validated temporary roots. Never log or retain audio, transcripts, model content, absolute paths, capabilities, lease tokens, credentials, raw exceptions, or unrestricted environment dumps.
- Preserve unrelated dirty-worktree files. Stage explicit packet paths only, use conventional commits, push without rewriting remote history, and bind every CI assessment to the exact pushed SHA on pull request 58 (or its verified successor if the PR head changes).
- Treat all C++ warnings, build failures, formatting failures, linter/static-analysis findings, sanitizer findings, native test failures, fuzz/TSan/GCC/hardening failures, and Windows MSVC failures selected by the current workflow as packet blockers.
- A final Windows-discovered shared-code fix must rerun every affected Linux/shared gate before Packet 15 can complete.
