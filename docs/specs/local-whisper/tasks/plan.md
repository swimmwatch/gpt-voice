# Implementation Plan: Local Whisper

Status: Approved

Approval: `approval.plan` revision 7 records the user's 2026-08-01 directive
that all representative Windows checks execute only in Task 17. Revision 7
applies `planning.native-cpp-windows-gate` revision 2 across Tasks 01–16:
implementation, deterministic/source-contract checks, checked-in Windows CI,
and available non-Windows evidence may close an owner packet, while all real
Windows filesystem, process, engine, capability, lifecycle, native-quality,
package/install, and hardware execution is centralized in Task 17. Revision
6's canonical protocol and pinned OpenWhispr boundaries remain unchanged;
downstream numbering is unchanged.

## Goal

Deliver Local Whisper as an optional main-owned local Voice provider with two
pinned engines, exact model/runtime lifecycle, current-device validation,
explicit RAM/VRAM residency, hardened backend-specific sidecars, safe
downloads, and a complete settings/management UI. AMD remains untested Preview
and macOS remains a non-executable Planned skeleton.

## Sequencing

```text
01 -> 02 ----------------------------------------------------------┐
 └-> 03 -> 04 -> 05 -> 06 -> 07 -> 08 ─┐                          │
                                  └-> 09 ─┼-> 10 -> 11 -> 12       │
                                                   -> 13 -> 14 ----┤
03 -> 04 -> 05 -> 06 -> 07 -> 08/09 -> 15 ------------------------┤
01–15 -> 16 -------------------------------------------------------┤
01–16 -> 17 -------------------------------------------------------┤
06 + 17 -> 18 (future, non-release-blocking) ----------------------┘
```

- Tasks 02 and 03 may proceed independently after Task 01.
- Under `planning.native-cpp-windows-gate` revision 2, Tasks 01–16 own Windows
  implementation, deterministic/source-contract tests, and CI definitions but
  do not execute representative Windows checks. Task 17 alone executes and
  records the Windows filesystem, process, engine, capability, lifecycle,
  native-quality, package/install, and applicable hardware gates before
  release. Future AMD promotion evidence remains optional for the current
  untested Preview tier, but it may be executed only in Task 17.
- Tasks 08 and 09 may proceed in parallel after their shared catalog,
  filesystem, and supervisor contracts are complete.
- Task 15 may proceed after engine/artifact contracts stabilize while Tasks
  10–14 continue; it must finish before documentation and final integration.
- The hardened OpenWhispr choice is pinned to application commit `bf8b7e0` and
  whisper.cpp fork commit `dd18d11`. Tasks 07/08 may reuse only the persistent
  state-owner, serialized native context lifecycle/abort/free, and separate
  backend-pack build ideas; they reject loopback HTTP/upload, argv/private
  values, inherited environment, temporary audio, raw logs, PID/`taskkill`
  cleanup, shared mutable bin, automatic CPU fallback, published binaries, and
  mutable-release trust.
- Production artifact hosting is intentionally deferred. Task 15 must provide
  deterministic signed local fixtures and the complete protected publication
  contract; a real origin, credentials, signing ceremony, and publication stay
  `MANUAL GATE` items. Task 17 cannot mark those release gates passed without
  separate evidence and authority.
- Task 18 is a future, non-release-blocking hardening packet. Its macOS work is
  compile-only and unavailable; any executable Apple Silicon path requires a
  new `/spec` decision before implementation.
- No task may add a dependency, publish an artifact, contact an external
  service, alter a support tier, or run destructive/hardware-specific manual
  procedures unless its packet names and receives the required authorization.

## Approval Boundary

Plan approval does not authorize implementation or a commit. Completed Task 07
still requires separate commit authority, and Task 08 requires a separate
execution decision. Each later `incremental-implementation` invocation executes
exactly one authorized packet, updates `todo.md` and `handoff.md`, and stops
before commit or the next packet.
