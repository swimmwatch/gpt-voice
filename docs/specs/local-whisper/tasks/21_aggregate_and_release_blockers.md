# Task 21: Aggregate Production Readiness And Release Blockers

## Outcome

Reconcile the immutable Linux and Windows technical evidence without rerunning
unchanged expensive profiles. Validate automated ownership, the complete
shared-candidate/Linux/Windows graph, seal `aggregateEvidenceDigest`, validate
qualification-to-production allowed deltas, protected
production trust/legal/provenance/SBOM/notice/redistribution evidence, the
production-purpose package, and final distribution origins. Produce one
privacy-safe aggregate production-readiness and release-blocker report.

After a separately authorized runtime upload exists, download and install the
identical frozen runtime archive digest from its final GitHub Release origin
and verify public Hugging Face model transport. Never fabricate credentials,
legal approval, upload, platform evidence, or release authority.

## Task Contract

### Ownership and immutable reconciliation

The registry contains Tasks 01–21, plan revision 16, all 71 canonical
automated acceptance IDs exactly once, and at least one exact verification
command per task. Completed Tasks 01–18 remain primary owners of their prior
criteria; Task 19 owns `AC-AUTO-064`–`AC-AUTO-070` and `AC-AUTO-072`; Task 21
owns `AC-AUTO-071` plus its four existing aggregate criteria.

Reject aggregation when Linux and Windows differ on specification revision,
candidate SemVer/UTC/`candidateInputDigest`, shared source/model/corpus/
transfer/schema/Task 17 identity, or when either branch has a missing/backward/
duplicate/mixed input-profile-graph-result-index edge. Platform-specific
package, runtime, direct-engine, toolchain, catalog/origin, profile, and
predecessor identities are expected to differ but must remain confined to the
correct branch. Reject missing owner links, unknown statuses, impossible
transitions, private fields, unsupported evidence classes, Pass without
required evidence, or Not Applicable hiding a required row.

Every acceptance/manual/support/external row records one of `Pass`, `Fail`,
`Pending`, or `Not Applicable`, a stable reason, evidence class,
`candidateInputDigest`, relevant platform-graph/profile/evidence digest, and
specification revision 10.

### Qualification-to-production promotion

Production packaging accepts only the frozen qualified source commit and
runtime/model bytes plus protected production-purpose catalog/keyring/origin
inputs. Fixture, qualification, and production keys/purposes remain pairwise
disjoint. Production collection rejects disabled, fixture, qualification,
missing, substituted, or mismatched trust resources before package collection.

`AC-AUTO-071` compares qualification against altered fixture, executable,
native, model, setting/protocol, trust, origin, and package variants. Only
declared version/trust/catalog/origin/release metadata may differ. Every
executable or qualification-relevant delta invalidates prior technical evidence
and requires a new candidate rather than promotion.

Validate runtime-component redistribution, public-upstream model-download
facilitation, FLEURS use, licenses, checksummed provenance, component SBOM,
notices, artifact signature/key rotation/denylist evidence, and production
authority. A missing or unauthentic item is `Pending`/`Fail` as appropriate and
cannot be reclassified as a platform result.

### Final origins and transport parity

Task 19 loopback HTTPS evidence proves qualification transport only. After a
separately authorized upload, resolve the exact immutable
`https://github.com/swimmwatch/gpt-voice/releases/download/<exact-tag>/<exact-asset>`
origin through the signed production redirect policy, download the identical
archive length/SHA-256/signature, run bounded install parity, and confirm no
qualification/fixture trust is accepted.

Independently verify the exact public
`ggerganov/whisper.cpp` commit/file/length/SHA-256 model origin and signed
Hugging Face redirect policy without credentials or private headers. Never
replace final GitHub evidence with loopback evidence or replace public
Hugging Face evidence with a project mirror.

and production readiness. Missing external evidence is an explicit blocker,
not a fabricated platform failure or pass. Task 21 may produce an interim
truthful blocker report while external inputs or upload authorization are
missing, but remains incomplete until every required production-readiness gate
and `AC-MAN-014` passes.

## Failure And Rollback

- Preserve the shared candidate input and both platform graph/result/index
  branches. Aggregate output may be regenerated only from those same immutable
  inputs.
- A shared-input/common-model/corpus/schema/fixture mismatch returns to newly
  authorized Task 19 work. A Linux-only branch mismatch returns to Task 19; a
  Windows-only branch mismatch returns to Task 20. Never rewrite evidence to
  match the aggregate.
- Owner-packet failure names the exact primary owner and requires new
  authorization; Task 21 does not patch around it.
- Missing external/hardware/platform/origin evidence remains `Pending` and
  Task 21 incomplete. Privacy, trust, unauthorized delta, cleanup, or evidence
  integrity failures are blocking `Fail` results.
- Clean only exact Task 21 temporary output; never delete platform evidence,
  uploaded assets, production keys, or user data.
